# Window Shepherd v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Swift menu-bar Mac app that does everything the Hammerspoon window mover does (100% parity), plus the things a stranger needs: Accessibility onboarding, launch at login, About, Check for Updates and Quit.

**Architecture:** A Swift package, `WindowShepherdCore`, holds everything that can be tested without a screen: the shortcut model, clash rules, geometry, the auto-restore state machine, the job runner and the move engine. The engine talks to windows only through a `WindowSystem` protocol, so tests use a fake and the app uses the real Accessibility/CoreGraphics one. A thin AppKit/SwiftUI app (an Xcode project generated by XcodeGen) adds the status-bar menu, Carbon hotkeys, the settings window, onboarding and Sparkle. All state lives on the main actor. Every Accessibility call runs on a worker queue with a 0.5 s timeout, so the main thread never waits on another app.

**Tech Stack:** Swift 6.3 toolchain in Swift 5 language mode, macOS 14+, AppKit + SwiftUI, Carbon `RegisterEventHotKey`, `CGEventTap` (shortcut recorder), `SMAppService`, Sparkle 2 (SPM), XcodeGen, XCTest.

**Spec:** `~/CLAUDE/window-mover/docs/superpowers/specs/2026-10-19-window-shepherd-app-design.md` (with `2026-10-19-custom-shortcuts-design.md` beside it). Reference implementation: `~/CLAUDE/window-mover/hammerspoon/` at the window-mover repo's HEAD (`init.lua`, `shortcuts.lua`, `conflicts.lua`, `scan.lua`, `settings-window.lua`, `settings.html`, `known-shortcuts.lua`) and its tests in `~/CLAUDE/window-mover/tests/`. **When this plan says "port X", the Lua is the spec for behaviour, constants and user-visible wording.**

## Global Constraints

- macOS 14 (Sonoma) and newer; Swift; menu-bar only (`LSUIElement = YES`), no Dock icon.
- Bundle ID `com.windowshepherd.WindowShepherd`. Product name "Window Shepherd".
- **Nothing may hang or slow the Mac.** The only polling is the 2 s tick. Every Accessibility call has a 0.5 s timeout (`AXUIElementSetMessagingTimeout` on each app element) and runs off the main thread. A hung app costs at most one timeout per step.
- Shortcuts are always written in keyboard order ⌃ ⌥ ⌘ key ⇧ (e.g. `⌥⌘F`, `⌃⌥⌘2⇧`). Never use `NSMenuItem.keyEquivalent` to display them, because macOS draws ⇧ before ⌘.
- Nothing the user reads is drawn faint or disabled-grey. Reference-only menu rows are enabled items with a no-op action.
- No network traffic except Sparkle's update check.
- Public repo: no secrets (signing certs, notarization credentials, Sparkle private key), no private project names, no private notes. The local signing identity goes in the gitignored `Config/Local.xcconfig`.
- Tip link: `https://buymeacoffee.com/cccccccharles`. Website: `https://windowshepherd.com`. Sparkle feed: `https://cabaynes.github.io/window-shepherd/appcast.xml`.
- Author shown in About: Charles Baynes. License MIT.
- Constants (from `init.lua`): ALMOST 0.9; WINDOW_LIMIT 0.8 s; list-windows failure = error, or empty after > 0.4 s; RETRY_WAITS [2, 4] s; RETRY_FOR 120 s; job deadline `min(10 + 1.0 × windows, 120)` s; job step gap 0.02 s; FORGET_AFTER 30 days; save layouts when changed or every 600 s; two sightings 2 s apart; restore passes at +3 / +10 / +20 s; a restore that finds a job running re-checks after 5 s; unsettled safety net 60 s; stale job cleared at deadline + 5 s; CG window filter: layer 0, on screen, both sides > 80 pt.
- Tests: `swift test` at the repo root runs the Core tests; `scripts/build.sh` builds the app. A task isn't done until both are green.

## Review Focus

1. **A hung or very slow app** while a keyboard snap, a bulk move, a restore or a settings-window menu scan touches it. Expected: the main thread never waits; another snap still completes; the hung app is named as skipped after its retries. Test: Task 10 `testHungAppNeverBlocksMainActor`.
2. **The screens change mid-move, or a menu stays open across an unplug.** Expected: the stale target is refused ("<name> (n) isn't connected anymore"), a job running for the old setup stops, and nothing from it is saved. Tests: Task 10 `testScreenChangeMidMoveSavesNothing`, Task 14 `testMoveToGoneScreenIsRefused`.
3. **Windows that aren't in the on-screen list** (other Spaces, minimized, hidden apps). Expected: they're kept until unseen for 30 days, are never treated as closed, and are never recorded at a spot macOS dumped them in. Test: Task 11 `testUnseenWindowsKeptUntilThirtyDays`.
4. **A damaged or old saved config or layouts file, or a keyboard layout that lacks a saved key.** Expected: bad entries fall back to defaults with a log note, there's no crash, and the good entries are kept. Tests: Task 4 (ported sanitize tests) and Task 11 `testCorruptLayoutsFileStartsEmpty`.
5. **Odd displays:** two monitors of the same model, a display whose name is empty, no built-in display (clamshell). Expected: numbering stays 1 = laptop (if any), then left to right; same-model monitors are told apart by number; setup keys stay distinct. Test: Task 6 `testDestinationsClamshellAndTwins`.

**Threading rule (all Engine code):** `Shepherd`, `JobRunner`, `LayoutBook` and every piece of state are `@MainActor`. A step that must talk to an app does `await worker.run { … }`, where the closure runs on a serial background queue. Two workers exist: `jobWorker` for bulk jobs and restores, and `snapWorker` for single-window keyboard and menu moves, so a snap never queues behind a restore step (parity: "single-window moves run immediately rather than queueing behind an auto-restore"). Only `WindowSystem` methods marked *worker* may block.

## Phase 2 — The engine

### Task 6: Geometry, screens and placers

**Files:**
- Create: `Geometry/Geometry.swift`, `Geometry/Screens.swift`, `Geometry/Placer.swift`, `Tests/WindowShepherdCoreTests/GeometryTests.swift`

**Interfaces:**
- Produces (all rects are in global top-left coordinates, the space CG and AX use):
  ```swift
  public struct UnitRect: Codable, Equatable { public var x, y, w, h: Double }
  public struct Spot: Codable, Equatable { public var scr: String; public var unit: UnitRect }
  public struct ScreenInfo: Equatable { public let displayID: UInt32; public let uuid: String; public let name: String
    public let isBuiltin: Bool; public let frame: CGRect /* visible */; public let full: CGRect }
  public struct Destination: Equatable { public let screen: ScreenInfo; public let name: String; public let num: Int; public let isLaptop: Bool }
  public enum Geometry {
    static func place(_ u: UnitRect, in f: CGRect) -> CGRect
    static func centered(_ size: CGSize, in f: CGRect) -> CGRect          // shrink to fit, then center
    static func unit(of r: CGRect, in f: CGRect) -> UnitRect
    static func fit(_ r: CGRect, inside f: CGRect) -> CGRect              // hs ensureIsInScreenBounds
    static func flip(_ appKit: CGRect, primaryHeight: CGFloat) -> CGRect  // NSScreen → top-left
    static func screen(mostOf r: CGRect, in s: [ScreenInfo]) -> ScreenInfo?   // largest intersection (hs.screen.find(rect))
    static func whereIs(_ windowFrame: CGRect, in s: [ScreenInfo]) -> Spot?   // center inside .full → unit of .frame
    static func sameSpot(_ a: Spot?, _ b: Spot?) -> Bool                      // same scr, every field within 0.005
  }
  public enum Screens {
    static func live() -> [ScreenInfo]                       // NSScreen.screens order; uuid via CGDisplayCreateUUIDFromDisplayID ("?" if nil); builtin via CGDisplayIsBuiltin
    static func destinations(_ s: [ScreenInfo]) -> [Destination]   // Laptop first, then others by full.minX; name "Laptop" / screen.name or "Monitor" when empty
    static func setupKey(_ s: [ScreenInfo]) -> String        // sorted uuids joined "+"
    static func setupLabel(_ s: [ScreenInfo]) -> String      // sorted names (empty → "?") joined " + "
    static func next(after: ScreenInfo, in s: [ScreenInfo]) -> ScreenInfo   // NSScreen order, cyclic (hs screen:next())
    static func defaultFraction(_ d: Destination) -> Double  // 1.0 laptop, 0.9 monitor
  }
  public enum TargetScreen: Equatable { case own, fixed(uuid: String) }
  public enum Placer: Equatable {
    case unit(UnitRect, TargetScreen, fitInside: Bool = false)
    case center(TargetScreen)
    public func frame(for window: CGRect, screens: [ScreenInfo], main: ScreenInfo?) -> CGRect?   // nil = target screen gone
    public static func fraction(_ f: Double, on t: TargetScreen) -> Placer   // centered f×f unit
  }
  public func sizeLabel(_ f: Double) -> String   // "full" | "90%" | "60%"
  ```
