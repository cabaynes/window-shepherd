# windowshepherd.com Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A one-page windowshepherd.com with a playable replug demo, in a "Coming soon" state until the signed build exists.

**Architecture:** Static files in `site/` (no build step): `index.html`, `styles.css`, a pure demo model (`demo-model.js`, unit-tested with `node --test`) and a DOM view (`demo.js`) that animates it. A Chromium page check (`site/tests/check-page.cjs`) verifies layout, privacy and demo behaviour. GitHub Actions publishes `site/` to Pages at windowshepherd.com.

**Tech Stack:** HTML, CSS, vanilla ES modules; Node 25 `node --test`; playwright-core from `/opt/homebrew/lib/node_modules/@playwright/cli/node_modules/playwright-core` driving Playwright's bundled **Chromium** (never Chrome); Python 3 + Pillow for icons; GitHub Pages via Actions.

**Spec:** `docs/superpowers/specs/2026-11-24-website-design.md`. Copy source: `docs/website/content.md`.

## Review Focus

1. **Clicking fast or mid-animation** (Plug in while Unplug is still sliding, double clicks): the demo must end in the state of the last click, never with windows stranded between screens. → Task 1 `test rapid unplug then plug in ends home`; Task 3 check "rapid clicks".
2. **Monitor unplugged, then a scope/action button pressed:** actions must only use the laptop; "→ other screen" is disabled with the caption saying why. → Task 1 `test other-screen unavailable while unplugged`; Task 3 check.
3. **Phone width:** the scene must stay legible and inside the viewport at 360px, controls wrapping under it. → Task 2/3 page check at 360×740.
4. **Keyboard and screen-reader users:** every control is a `<button>` reachable by Tab, with `aria-pressed` on the scope toggle, and the caption is `aria-live="polite"`. → Task 3 check.
5. **Autoplay vs. the visitor:** the one automatic replug must stop the moment the visitor clicks anything and must not run under reduced motion. → Task 3 check "autoplay yields to a click".

### Task 1: Demo model

**Files:**
- Create: `site/demo-model.js`
- Test: `site/tests/demo-model.test.mjs`

**Interfaces:**
- Produces (ES module exports):
  - `createDemo(): DemoState` — `{ plugged: true, focused: 'chrome-1', windows: Win[] }` where `Win = { id, app, label, home: Place, at: Place }` and `Place = { screen: 1|2, x, y, w, h }` in 0–1 units of that screen (1 = laptop, 2 = monitor, as the app numbers them).
  - Windows (ids, app, home): `notes` Notes on 1 `{.06,.08,.6,.7}`; `chrome-1` Chrome on 2 `{.05,.08,.55,.75}`; `chrome-2` Chrome on 2 `{.40,.15,.55,.75}`; `code-1` VS Code on 2 `{.10,.20,.50,.70}`; `code-2` VS Code on 1 `{.30,.20,.65,.70}`; `messages` Messages on 2 `{.62,.50,.33,.42}`.
  - `unplug(s): Step[]` — every window on screen 2 moves to screen 1, cascading from `{x:.04,y:.06}` by `.05` per window, keeping its w/h clamped to fit; sets `plugged:false`. One step.
  - `plugIn(s): Step[]` — two steps: step 1 `who:'macos'` moves `chrome-1` and `messages` home (macOS puts a couple back); step 2 `who:'shepherd'` moves every other window not at home. Sets `plugged:true`.
  - `act(s, scope: 'window'|'app'|'all', action: 'full'|'ninety'|'center'|'other'): { steps: Step[], keys: string, error?: string }` — targets: focused window / every window of the focused window's app / all windows. Sizes on the target's own screen: full `{0,0,1,1}`, ninety `{.05,.05,.9,.9}`, center keeps w/h and centres. `other` sends each target to the other screen: full screen on the laptop, 90% on the monitor (content.md 5.3).
  - `Step = { who: 'macos'|'shepherd'|'you', moves: { id, to: Place }[], caption: string }`. Each function also mutates `s` to the final state, so a later call always starts from where the last call ends (Review Focus 1).
  - `shortcutFor(scope, action, fromScreen: 1|2): string` — content.md 5.4: window `⌥⌘F`/`⌥⌘G`/`⌥⌘C`, other → `⌥⌘2` from the laptop, `⌥⌘1` from the monitor; app adds ⌃ (`⌃⌥⌘F`, `⌃⌥⌘G`, `⌃⌥⌘C`, `⌃⌥⌘2`); all → sizes have no key: return `'menu: Everything'`; all + other → `⌃⌥⌘2⇧` (or `⌃⌥⌘1⇧` from the monitor).
  - `focus(s, id)`.

- [ ] **Step 1: Write the failing tests** (`node:test` + `node:assert/strict`):
  - `createDemo has six windows, four on the monitor`
  - `unplug puts every window on the laptop, inside it` (every `at.screen === 1`, `x+w <= 1`, `y+h <= 1`)
  - `plugIn: macOS puts back exactly chrome-1 and messages, then Window Shepherd the rest` (step 0 who `macos` ids `['chrome-1','messages']`; after both steps every `at` equals `home`)
  - `rapid unplug then plug in ends home` (unplug, plugIn, unplug, plugIn without rendering → all home)
  - `act app ninety resizes both Chrome windows on their own screen` (`focus(s,'chrome-1')`, both Chrome `at` = `{screen:2,x:.05,y:.05,w:.9,h:.9}`, `keys === '⌃⌥⌘G'`)
  - `act all other while plugged sends laptop windows to the monitor at 90% and monitor windows to the laptop full` and `keys === '⌃⌥⌘2⇧'`
  - `other-screen unavailable while unplugged` (after unplug, `act(s,'window','other').error` is a non-empty string and `steps` is empty)
  - `center keeps size` (w/h unchanged, `x === (1-w)/2`)
  - `shortcutFor covers the table` (the values listed above, one assert each)
